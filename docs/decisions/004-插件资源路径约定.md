# 004 — 插件资源路径约定

**日期**: 2026-10-01

**状态**: 已通过

## 背景

插件页面通过 `/p/{id}/{capability}/` 提供，但示例组件引用了站点根路径 `/favicon_256.ico`，导致图片请求脱离插件路由。脚手架生成的 manifest 也可能声明一个未打包的默认图标。

## 决定

插件页面的公开资源使用 Vite `base` 路径构建；在组件代码中引用 `import.meta.env.BASE_URL`，在 HTML 中引用 `%BASE_URL%`。manifest 的 `plugin.icon` 仅在配置了图标并成功复制到插件包根目录后声明。插件 ID 和包内路径在安装及提供静态文件时校验。插件页面与 API 使用同一 loopback 来源，因此静态文件和配置 API 不开放跨站 CORS。

## 原因

Vite 已知道每个插件能力的部署前缀，沿用它可以让开发和打包使用同一套资源引用方式。显式校验图标和路径能尽早暴露错误，避免安装成功后出现断图或访问插件目录之外的文件。

## 影响

- 正面影响：组件图片、页面图标和 manifest 图标都能定位到包内资源；打包完成后才返回构建成功；其他网站无法通过浏览器跨站读取插件配置。
- 代价：旧插件中以站点根路径引用的公开资源需要改为基于 `BASE_URL` 的路径；图标文件缺失会使构建失败。
- 后续事项：逐步将已有插件中的根路径资源引用迁移到该约定。

## 备选方案

- 在主程序中把根路径请求猜测为当前插件资源：同一服务器可能同时服务多个插件，无法可靠确定所属插件。
- 始终声明默认 `icon.png`：脚手架不生成该文件，会产生无效的 manifest 引用。
